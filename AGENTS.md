## Project Overview

pyclesperanto is the python package / wrapper for clesperanto, a GPU-accelerated Image Processing library.
The actual GPU kernels/core C++ library (`clic`) is a separate dependency, fetched at build time; this repo
wraps it for OpenCL, CUDA, and Metal via pybind11.

## Repo structure

```
src/clic/           git submodule/fetched dependency: the core C++ clesperanto (clic) library
src/wrapper/        pybind11 C++ bindings around clic, split by tier (tier1_.cpp ... tier8_.cpp, core_.cpp, array_.cpp, ...)
backends/opencl/    OpenCL backend package (pyclesperanto_opencl): CMakeLists.txt + pyproject.toml, builds the compiled extension
backends/cuda/      CUDA backend package (pyclesperanto_cuda), same layout as opencl
backends/metal/     Metal backend package (pyclesperanto_metal), macOS only, same layout
pyclesperanto/       pure-python package: public API, dispatches calls to whichever backend is installed/active
tests/               pytest suite, organized by feature (filtering, morphology, transform, labeling, ...)
scripts/             build/repair helper shell scripts for CI (linux/windows, cuda/opencl, wheel repair)
docs/                documentation sources and demos
CMakeLists.txt       convenience top-level CMake stub (backends are built independently; see comments in file)
pyproject.toml       metadata + hatch build config for the main `pyclesperanto` python package
hatch_build.py       hatch metadata hook: pins backend package versions (opencl/cuda/metal) to match main version
pixi.toml            pixi environment/task definitions for local dev (see "Build & test" below)
```

Each backend (`backends/opencl`, `backends/cuda`, `backends/metal`) is an independent, installable
python package with its own `pyproject.toml` + `CMakeLists.txt`. Building a backend compiles the
pybind11 extension (`src/wrapper`) against `src/clic` and the backend-specific GPU SDK. The main
`pyclesperanto` package has no compiled code itself — it is pure python and picks up whichever
backend(s) are installed at import time (see `pyclesperanto/_backend.py`).

## Code organisation (`pyclesperanto/`)

- `_backend.py` — backend detection/selection (opencl/cuda/metal), lazy import of the compiled extension.
- `_core.py`, `_array.py`, `_memory.py`, `_execute.py` — core device/array/memory management and kernel execution.
- `_tier1.py` ... `_tier8.py` — the public image-processing operations, organized in tiers matching the
  C++ wrapper (`src/wrapper/tier*_.cpp`) and the underlying clic library. Tiers roughly go from simple
  per-pixel ops (tier1) to complex composite/analysis ops (tier8). `tierN.py` and `_tierN.cpp` are autogenerated
- `_transform.py`, `_functionalities.py`, `_operators.py` — geometric transforms, array ops/operators.
- `_categories.py` — operation categorization/metadata used for docs and tooling (e.g. napari, bia-bob).
- `_decorators.py`, `_utils.py` — shared helpers/decorators used across tier modules.
- `_interroperability.py` — conversions to/from numpy, dask, etc.
- `_bia_bob_plugins.py` — integration entry point for the bia-bob assistant plugin.
- `__experimental__/` — unstable/in-progress API, not part of the stable public surface.

New operations are typically added by: implementing/wrapping the op in `src/clic` + `src/wrapper`,
exposing it through the matching `_tierN.py` module, and adding a test under `tests/`.

## Package and environment management

- The project is defined by a `pyproject.toml`, a `hatch_build.py` script, and a `CMakeLists.txt`.
- Each backend is defined by its own `pyproject.toml` and `CMakeLists.txt` under `backends/`.
- Local environment, build and test tasks are managed via `pixi.toml` (uses `pixi run <task>`).
- Non-python dependencies used by the backends (e.g. clic, pybind11 headers) are fetched at build
  time by CMake and land in each backend's `build/` folder.

## Build & test (via pixi)

- `pixi run build-ocl` — build/install the OpenCL backend + main package.
- `pixi run build-cuda` — build/install the CUDA backend + main package.
- `pixi run build-metal` — build/install the Metal backend + main package (macOS only).
- `pixi run build-macos` — OpenCL + Metal + main package.
- `pixi run build-all` — all three backends + main package.
- `pixi run test-ocl` / `test-cuda` / `test-mtl` — run tests filtered by backend (`pytest -k <backend>`).
- `pixi run test-all` — run the full test suite.
